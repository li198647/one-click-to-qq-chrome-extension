# 一键发到 QQ

在浏览器里选中一段文字，按一下快捷键，**内容就发到你手机 QQ 上了**。

核心场景：在电脑浏览器里看到一段文字或一个链接（商品页、文章、地址、验证码），想立刻在手机上打开或存下来 —— 不用切窗口、不用拖文件、不用扫码。

---

## 架构

三段式，缺一不可：

```
┌─────────────────┐      HTTP       ┌──────────────┐    WebSocket    ┌──────────────┐
│  Chrome 扩展     │ ─────────────→ │   本地桥      │ ─────────────→ │  QQ 开放平台  │
│  （浏览器里的入口）│  127.0.0.1:18761│  （Python）   │   长连接        │  官方机器人   │
└─────────────────┘                 └──────────────┘                 └──────┬───────┘
                                                                            │
                                                                     你的手机 QQ
```

- **Chrome 扩展**只负责「读内容」和「给你一个浏览器里的入口」。
- **本地桥**是跑在你自己电脑上的 Python 小程序，通过 QQ 官方机器人开放平台收发消息。
- 浏览器出于安全沙箱，**没有任何一条路能直接碰到 QQ**，所以中间必须有一个本地程序当桥。

## 为什么这么设计

| 方案 | 结论 |
|---|---|
| **本方案：官方机器人 + 本地桥** | ✅ 采用。不碰 QQ 通信协议、不动桌面客户端、**零封号风险**，也不依赖桌面是否解锁 |
| UI 自动化（模拟键鼠操作桌面 QQ） | ❌ 否决。QQ NT 是 Electron，聊天区 UIA 树读不到输入框；且要求桌面必须解锁、窗口不能在屏幕外 |
| 第三方协议（NapCat / OneBot） | ❌ 否决。属非官方协议，主号有封号风险 |
| 网页版 QQ | ❌ 不可行。`web.qq.com` / SmartQQ 已于 2019-01-01 停运 |
| 飞鸽 / Syncthing | ❌ 不适用。它们没有浏览器里的入口，而"入口"正是这个项目的全部价值 |

## 目录结构

```
├── extension/              Chrome 扩展（MV3）
│   ├── manifest.json       扩展定义：权限、快捷键、图标
│   ├── background.js       主逻辑：抓内容 → 发本地桥 → 成功/失败反馈
│   ├── offscreen.html/js   读剪贴板用（MV3 的 service worker 里没有 DOM）
│   ├── popup.html/js       点图标查看桥状态 + 手动发送兜底
│   └── icons/              16 / 48 / 128 图标
│
├── bridge/                 本地桥（Python）
│   ├── qq_bridge.py        主程序：aiohttp 本地服务 + botpy WebSocket
│   ├── config.example.json 配置模板（复制成 config.json 再填）
│   ├── start_bridge.bat    双击启动
│   ├── send_test.py        命令行工具：查状态 / 发消息 / 看日志
│   └── probe_url.py        链接探针：验证 QQ 会不会过滤带链接的消息
│
└── tools/                  开发期的探针脚本（UI 自动化探索的存档）
    ├── probe_windows.py    枚举本机窗口，判断 QQ 客户端形态
    ├── probe_uia*.py       读取 QQ 的 UI Automation 树（逐级开启读屏标志）
    ├── shot_qq.py          截取 QQ 窗口画面
    ├── net_check.py        检测 QQ API 域名连通性（防代理 fake-IP 坑）
    └── make_icons.py       生成扩展图标
```

## 快速开始

### 第 1 步 · 准备一个 QQ 机器人

1. 打开 <https://q.qq.com/> → 注册（**个人主体**即可，身份证 + 手机 + 人脸，不需要企业资质）
2. 创建机器人 → 记下 **AppID**，生成 **AppSecret**（⚠️ 只在生成时明文显示一次）
3. 左侧「**开发设置**」→ 找到「**开发体验号码设置**」→ 点「+ 添加用户」→ 填**你自己的 QQ 号** → 保存后扫码把机器人加为好友
   - 旧文档里这一步叫「开发管理 → 沙箱配置 → 消息列表配置」，新版已改名
4. 手机 QQ 的消息列表里会出现你的机器人 → **给它发一句话**（桥需要靠这句话拿到你的 openid）

> 「服务范围 → 好友（私聊）→ 允许被其他 QQ 用户添加使用」**保持关闭**即可。关闭时管理员和开发体验成员仍可添加，正是自用所需。
>
> 「服务器 IP 白名单」**不用填**。官方文案：未设置时所有来源 IP 都会被允许调用。

### 第 2 步 · 启动本地桥

```bash
cd bridge
# 把 config.example.json 复制成 config.json，填入 appid 和 secret
python qq_bridge.py
```

依赖：`pip install qq-botpy`（Python 3.8+）

启动成功后日志会显示：

```
[botpy] 机器人「你的机器人名」启动成功！
[botpy] 心跳维持启动...
本地服务已启动: http://127.0.0.1:18761
```

**这个窗口要一直开着。** 桥关了就发不出去。

### 第 3 步 · 装 Chrome 扩展

1. 地址栏输入 `chrome://extensions`
2. 右上角打开「**开发者模式**」
3. 左上角点「**加载已解压的扩展程序**」→ 选中 `extension` 文件夹
4. 去 `chrome://extensions/shortcuts` 确认 `Ctrl+B` 已分配
   - ⚠️ 未打包的开发版扩展，manifest 里的默认快捷键**不会自动生效**，需要在这里手动设一次

---

## 用法

按下 `Ctrl+B`，内容按三级优先级自动选取：

| 优先级 | 来源 | 说明 |
|---|---|---|
| ① | **选中的文字** | 在页面上划选一段文字，**不需要先 Ctrl+C** |
| ② | **剪贴板** | 没有选中内容时，读剪贴板 |
| ③ | **页面标题 + 链接** | 前两者都空时，发当前页面的标题和 URL |

反馈：

- 成功 → 扩展图标跳出**绿色 `OK`**（2.5 秒后消失）
- 失败 → 图标常驻**红色 `ERR`** + 系统通知写明原因（桥没启动 / 机器人没连上 / 具体报错）

**绝不假装成功。**

## 实测结论

### ✅ 带链接的消息能正常发出去

官方文档 8.3 节《消息URL白名单配置》写的是：机器人下发消息里的链接域名必须**提前报备**，且「域名需提前进行 ICP 备案」。第三方资料更直白地说含 URL 的消息会被**静默过滤**。

实测（`bridge/probe_url.py` 连发 5 种形态）结果：

| # | 形态 | 接口返回 | 手机是否收到 |
|---|---|---|---|
| 1 | 纯文本（对照） | 200 `ok=True` + msg_id | ✅ |
| 2 | `https://www.baidu.com` | 200 `ok=True` + msg_id | ✅ |
| 3 | `www.baidu.com` | 200 `ok=True` + msg_id | ✅ |
| 4 | `baidu.com` | 200 `ok=True` + msg_id | ✅ |
| 5 | 文字 + 淘宝链接 | 200 `ok=True` + msg_id | ✅ |

**5 条全部到达手机，且 URL 被 QQ 自动识别成可点击的蓝色链接** —— 那条"必须备案"的限制在**沙箱环境（未上架）下并未生效**。

> ⚠️ 这是腾讯当前的行为，策略可能变化。桥里保留了链接检测预警，一旦发链接开始失败你会立刻看到提示。

### ✅ 主动消息配额

官方 API 文档：**个人认证 = 单聊 1000 条 / 用户 / 天**（Bot 维度 10 qps，单关系 20 qpm）。

> 网上流传的"每月只有 4 条"是**误读** —— 那是"互动召回消息的 4 个时间周期"（当天 / 1-3 天 / 3-7 天 / 7-30 天），不是月配额。

## 已知限制

| 限制 | 说明 |
|---|---|
| **必须先发过一句话** | 腾讯限制：只有你主动给机器人发过消息，它才能主动找你。openid 到手后写入 `state.json`，之后长期可用 |
| **可以在 QQ 端关闭** | 机器人资料卡里可以关掉"接收主动消息"，关了之后发送一律失败（桥会捕获 `on_c2c_msg_reject` 事件并明确报错） |
| **消息在独立会话里** | 内容出现在「你的机器人」这个独立会话，**不是**「我的手机」会话 |
| **只发文字** | 当前版本不支持图片（剪贴板图片、网页截图） |
| **桥必须常驻** | 电脑关了、桥进程挂了就发不出去。桥会明确报错，不会静默失败 |

## 开发笔记（踩过的坑）

- **Chrome 扩展目录里不能有下划线开头的文件**。`_` 是 Chrome 系统文件保留前缀，任何 `_xxx` 文件都会导致整个扩展**加载失败**，且报错信息误导性地显示为"无法加载清单"。
- **MV3 的 service worker 里没有 DOM**，读剪贴板必须用 `chrome.offscreen` API 建一个 offscreen 文档（`reasons: ['CLIPBOARD']`）。
- **不申请 `tabs` 权限**（免得弹"读取您的浏览记录"）：页面标题和 URL 一律靠 `chrome.scripting.executeScript` 在页面内取。`activeTab` 权限在快捷键触发时同样会被授予。
- **未打包扩展的默认快捷键不会自动生效**，必须去 `chrome://extensions/shortcuts` 手动设一次。
- **Chromium/Electron 应用默认不构建无障碍树**。要先打开 Windows 的"读屏软件正在运行"标志（`SPI_SETSCREENREADER`），UI Automation 才能读到 Electron 应用的 DOM 结构 —— 这是 `tools/probe_uia*.py` 能跑通的前提。
- **代理的 fake-IP 模式可能干扰 Python 直连**。`tools/net_check.py` 会验证域名是否解析到真实 IP。
